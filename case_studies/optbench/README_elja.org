#+title: Elja OptBench (CI-NEB vs OCINEB)
#+options: toc:nil

RONEB was renamed to OCINEB. =config_roneb.ini= is the OCINEB
(=ci_mmf = true=) method; =config_nebci.ini= is CI-NEB.

Morse Pt-island, 59 endpoint pairs, shipped INI files. Runs on Elja
(=ssh elja=, account =chem-ui=, partition =any_cpu=). Compute nodes
do not compile; =eonclient= comes from conda-forge =eon= 3.2.0 on
the login node.

#+begin_src bash
ssh elja
cd ~/Git/Github/HaoZeke/nebmmf_repro
# once:
micromamba create -y -p ~/micromamba/envs/eon320 -c conda-forge eon=3.2.0
export EONCLIENT=$HOME/micromamba/envs/eon320/bin/eonclient

cd case_studies/optbench
mkdir -p logs
sbatch --export=ALL,EONCLIENT elja_optbench.sbatch
#+end_src

Array 0-58 is one task per pair; each task runs CI-NEB then
OCINEB. Cap 20 concurrent (=chem-ui= MaxJobs is 30; MaxSubmit
is 100, so do not split into 118 array slots).

Job 1790989 finished. Force calls (destroyed-after) on all 59 pairs:

| method | n | mean | median | min | max |
| cineb | 59 | 408.9 | 357 | 172 | 1182 |
| mmf (OCINEB) | 59 | 264.4 | 297 | 92 | 594 |

The Snakefile is the real driver. Packing on Elja is Flux inside
one Slurm allocation (same shape as
=gpr_optim/bench/elja/scripts/sbatch_flux_in_slurm.sh=), not a
second Slurm array:

#+begin_src bash
cd case_studies/optbench
export EONCLIENT=$HOME/micromamba/envs/eon320/bin/eonclient
FLUX_SBATCH_PARTITION=any_cpu FLUX_SBATCH_ACCOUNT=chem-ui \
  FLUX_SBATCH_CPUS=16 FLUX_SNAKE_JOBS=16 \
  bash elja_flux_in_slurm.sh
#+end_src

Needs =flux= and =snakemake --executor flux= on PATH. Completed
=results.dat= / =neb.dat= are skipped; leftover work is plots.
